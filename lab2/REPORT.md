## 1. Цель работы

Научиться создавать процессы, перенаправлять их ввод-вывод и передавать данные между процессами через pipe.

## 2. Задание

Родительский процесс создаёт два дочерних. Первой строкой пользователь вводит имя файла, который открывается на запись для child1, второй строкой — для child2. Дальше родитель принимает строки произвольной длины и пересылает их в pipe1 или pipe2 по правилу фильтрации: **с вероятностью 80% в pipe1, иначе в pipe2**. Дочерние процессы **удаляют из строк все гласные** и пишут результат в стандартный вывод (он перенаправлен в свой файл). Родитель и дети — разные программы.

## 3. Архитектура

```
                          ┌── pipe1 (80%) ──► child1: stdin = pipe1, stdout = файл 1
stdin ──► parent ─────────┤
 (имена файлов, строки)   └── pipe2 (20%) ──► child2: stdin = pipe2, stdout = файл 2
```

Порядок работы родителя: два имени файла → `open` обоих на запись → `pipe` ×2 → два раза `fork` + в ребёнке `dup2`/`close`/`execl` → закрыть файлы и концы чтения → читать строки и писать в выбранную трубу → при конце ввода закрыть концы записи → `waitpid` обоих.

| Файл | Что делает |
|---|---|
| `parent.c` | родитель: имена файлов, `open`, `pipe`, запуск детей, фильтр 80/20, ожидание |
| `process.c/.h` | `start_child` (`fork` + `dup2` + `close` + `execl`), `wait_child` (`waitpid`) |
| `child.c` | ребёнок (одна программа для child1 и child2): читает stdin, пишет строки без гласных в stdout |
| `vowels.c/.h` | удаление латинских и русских (UTF-8) гласных |

Сборка `make`, тесты `make test`. Сообщения с PID все процессы пишут в stderr.

## 4. Ключевые фрагменты кода

Создание ребёнка (`process.c`). Между `fork` и `exec` ребёнок подменяет stdin и stdout и закрывает все исходные номерки, в том числе конец записи чужой трубы:

```c
pid_t pid = fork();
if (pid == -1) {
    perror("parent: fork");
    return -1;
}
if (pid > 0)
    return pid;

if (dup2(in_fd, STDIN_FILENO) == -1) { perror("child: dup2 stdin"); _exit(1); }
if (dup2(out_fd, STDOUT_FILENO) == -1) { perror("child: dup2 stdout"); _exit(1); }
for (int i = 0; i < count; i++)
    close_or_report(fds_to_close[i]);

execl(path, name, (char *)NULL);
perror("child: execl");
_exit(1);
```

Фильтрация строк (`parent.c`):

```c
while ((length = getline(&line, &capacity, stdin)) != -1) {
    int to_pipe1 = rand() % 100 < 80;
    int fd = to_pipe1 ? pipe1[1] : pipe2[1];
    if (write(fd, line, length) != length) {
        perror("parent: write в трубу");
        exit_code = 1;
        break;
    }
}
```

Завершение (`parent.c`). Закрытие концов записи даёт детям EOF, без него дети ждали бы данных, а родитель — детей:

```c
close_or_report(pipe1[1]);
close_or_report(pipe2[1]);
if (wait_child(child1) != 0)
    exit_code = 1;
if (wait_child(child2) != 0)
    exit_code = 1;
```

Краевые случаи: пустое имя файла, отсутствие второго имени и невозможность создать файл дают ошибку с кодом 1; ошибки всех системных вызовов печатаются через `perror`; `SIGPIPE` игнорируется, поэтому смерть ребёнка даёт родителю ошибку `EPIPE`, а не падение; если не создался второй ребёнок, родитель закрывает всё и дожидается первого.

## 6. Выводы

1. Написаны две программы: родитель распределяет строки между двумя детьми через два канала, дети пишут результат в свои файлы.
2. Перенаправление stdin и stdout детей делается через `dup2` между `fork` и `exec`: таблица дескрипторов сохраняется после `exec`, поэтому программа `child` не знает про трубы и файлы.
3. Каждый процесс должен закрыть лишние концы труб. Если ребёнок держит конец записи чужой трубы или родитель не закроет концы записи после ввода, дети не получат EOF и программа зависнет во взаимоблокировке.
4. Все системные вызовы проверяются, родитель ждёт обоих детей через `waitpid`, зомби не остаётся.
