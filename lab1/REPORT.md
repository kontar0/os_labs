## 1. Цель работы

Снять трассу системных вызовов стороннего ПО с помощью `strace` и составить его профиль: какие группы вызовов используются и для какого функционала.

## 2. Исследуемое ПО и способ снятия трассы

ПО: `bash` 5.2 (Linux-аналог `cmd`), Ubuntu 24.04 в Docker, aarch64. Инструмент: `strace` 6.8.

```sh
strace -f -y -o bash.log bash -c 'echo hello > out.txt; cat out.txt | wc -l; rm out.txt'
```

`-f` следить за дочерними процессами, `-y` показывать, что стоит за дескриптором, `-o` писать в файл. Сводка той же команды с `-c` (количество вызовов): [summary.txt](summary.txt).

Результат: [bash.log](bash.log), 355 вызовов, 3 процесса: 149 bash (в конце становится `rm`), 150 `cat`, 151 `wc`.

## 3. Профиль системных вызовов

| Группа | Вызовы | Всего | Для чего |
|---|---|---|---|
| Подготовка программы при запуске | `mmap`, `mprotect`, `munmap`, `brk`, `openat`/`read`/`close` для `libc.so.6` и др. | 133 | загрузка libc после каждого `execve` (4 раза), одинаково у любой программы |
| Процессы | `clone` 2, `execve` 4, `wait4` 3, `exit_group` 3, `getpid`, `getppid` | 20 | создать процессы для `cat` и `wc`, запустить в них программы, дождаться их |
| Поиск программы | `newfstatat` 35, `faccessat` 8, `getuid` и др. | 80 | найти `cat`, `wc`, `rm` по каталогам `PATH` и проверить право на запуск |
| Файлы | `openat` 2, `read` 4, `write` 3, `close` 19, `unlinkat` 1 и др. | 36 | открыть, прочитать, записать и удалить `out.txt`, закрыть лишние дескрипторы |
| Перенаправление и труба | `pipe2` 1, `dup3` 4, `fcntl` 6 | 11 | `>` и `\|`: создать трубу, подменить stdin/stdout |
| Сигналы | `rt_sigaction` 31, `rt_sigprocmask` 18, `rt_sigreturn` 1 | 50 | реакция на Ctrl+C и на завершение ребёнка (SIGCHLD) |
| Служебное | `ioctl`, `socket`, `connect`, `uname` и др. | 25 | bash узнаёт терминал, имя пользователя, имя машины |

В трассе `clone` вместо `fork`, `dup3` вместо `dup2`, `pipe2` вместо `pipe`, `wait4` вместо `waitpid`: это вызовы ядра, через которые glibc реализует функции C.

## 5. Сквозной профиль

### ЛР2: процессы и каналы ([../lab2/docs/strace.log](../lab2/docs/strace.log))

| Вызов в трассе | В коде | Зачем |
|---|---|---|
| `openat(..."tests/data/basic.txt", O_RDONLY) = 3` | `open` | файл с числами |
| `pipe2([4, 5], 0)` | `pipe` | pipe1 |
| `clone(...) = 1660` | `fork` | создать ребёнка |
| `dup2(3, 0)`, `dup2(5, 1)` | `dup2` | stdin ребёнка = файл, stdout = pipe1 |
| `execve("./child", ...)` | `execl` | запустить программу child |
| `write(1, "6\n")` / `read(4, "6\n")` | `write` / `read` | ребёнок пишет сумму, родитель читает |
| `wait4(1660, ...)` | `waitpid` | дождаться ребёнка |

## 6. Выводы

1. Составлен профиль `bash`: 355 вызовов в 7 группах. Больше трети из них это подготовка программы при запуске, а не сами команды.
2. Основа работы оболочки: `clone` создаёт процесс, `dup3` подменяет stdin/stdout для `>` и `|`, `execve` запускает программу, `wait4` ждёт её завершения.
3. Ошибки `ENOENT` в трассе это поиск программы по `PATH`, а не сбой.
